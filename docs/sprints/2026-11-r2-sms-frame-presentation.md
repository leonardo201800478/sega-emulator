# Sprint R2 — SMS VDP frames on Slint / WGPU 30 / Vulkan

**Baseline:** `21debccf906583d536ee963d5a41de786cdf3e35` (R1 merged)
**Branch:** `feat/r2-sms-frames-slint-wgpu`
**Status:** implementation candidate; CI and physical Windows validation pending.

## Objective

Connect completed SMS VDP frames from the existing `SmsTemporalWorker` to the R1 Slint/WGPU 30/Vulkan texture path without changing hardware timing or moving machine ownership into the GUI.

## Architectural invariants

- `SmsTemporalWorker` owns `SmsTemporalMachine` and its worker thread.
- `MachineScheduler` remains the only authority for CPU, VDP, PSG and bus time.
- GUI callbacks issue coarse-grained start/pause commands only.
- No instruction callbacks, GUI-driven cycles, or blocking GPU waits.
- `VideoFrame` remains immutable; `FrameMailbox` remains bounded and latest-frame-wins.
- Pixel conversion and texture upload happen only after a complete frame is published.
- CPAL remains R3; SDL3 remains R4.
- Existing D3D12 worker support is not used by the Slint/WGPU desktop path and is not removed until its remaining consumers and CI coverage are audited.

## R2.1 implementation scope

1. Add direct desktop dependencies on `sega-sms-runtime` and `sega-video-runtime`.
2. Load an SMS ROM from the command line and select a supported region.
3. Create `SmsTemporalWorker`, attach an externally owned `FrameMailbox`, and expose Start/Pause UI controls.
4. Poll the mailbox on the presentation timer; never poll or advance the Scheduler from the GUI.
5. Convert RGB888 to RGBA8 while respecting `VideoFrame::row()` and row stride.
6. Upload the newest complete frame through Slint's WGPU 30 queue.
7. Detach the producer before closing the mailbox and releasing the host resources.
8. Add tests for conversion, padding, alpha, pixel-format rejection and worker-to-mailbox publication.

## Required validation

Run the Windows x64 Slint/WGPU CI job with fmt, Clippy, tests and Release build. On physical Windows/Vulkan hardware, load a legally obtained SMS ROM and confirm:
- adapter reports Vulkan;
- the image is generated by the SMS VDP, not a synthetic pattern;
- frame sequence advances while running and stops while paused;
- resume continues presentation;
- resizing preserves aspect ratio;
- closing the window detaches the worker mailbox and emits clean teardown;
- no panic or temporal regression occurs.

Do not classify CI compilation as proof of physical rendering. Do not claim renderer recreation in-process until it is separately exercised.

## Implementation notes

The current SMS worker already publishes 256x192 RGB888 frames from `machine.framebuffer()` after complete frames. The desktop host must consume that contract; it must not introduce a second VDP framebuffer or alter the scheduler. The first implementation intentionally retains the worker's existing frame copy and converts pixels at the host boundary.


## R2.2 — menu migration

The Slint host now exposes the legacy menu groups (Sistema, Arquivo, Vídeo, Áudio, Controles, Opções and DEBUG). Implemented before R3/R4:
- optional command-line ROM startup and ROM path entry for SMS/BIN ROMs;
- in-session recent-ROM shortcut, close-ROM and exit actions;
- worker-backed Start/Pause/Stop/Reset/Step-frame and ROM replacement;
- region selection applied when a new worker is created;
- 4:3, 1:1 and 16:9 presentation viewport selection;
- immutable Z80 debug snapshot and bounded trace enable/disable.

Intentionally deferred and visibly disabled:
- physical audio output/device/backend/volume (R3 / CPAL);
- keyboard/gamepad event collection and remapping (R4 / SDL3);
- FPS overlay size/position; OS fullscreen and source-frame FPS visibility are now implemented but require physical validation;
- full debugger viewport with breakpoints, memory inspection and trace rendering;
- persistent recent-ROM history and settings.

All machine operations remain coarse-grained worker commands. The GUI does not execute CPU instructions or advance Scheduler time. Region changes are applied on ROM load; the currently running machine is not mutated in place.


## R2.3 — preferences and ROM history

The Slint host now restores/saves user presentation preferences under `%APPDATA%\\Sega Emulator\\` and maintains up to ten recent ROM paths. Supported persisted values: region, aspect ratio, FPS visibility, status-footer visibility and FPS text size. ROM history is path-only and does not auto-load a ROM at startup. The menu provides explicit user selection to reopen a recent path. No emulated machine state is serialized.
